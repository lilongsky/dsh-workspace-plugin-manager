# 验证说明

版本：`0.2.0-alpha.2`。验证日期：2026-10-19 至 2026-10-20。宿主接口目标：DSH `0.2.1-rc.2`。

## 已验证

| 范围 | 环境 | 结果 |
| --- | --- | --- |
| 核心管理器与通用加载 | 隔离 SDK；系统 Node 26.12.0 | 31/31 通过 |
| 原生配置持久化 | 临时 profile；原生 Loader、Settings、ConfigEditor | 落盘与销毁/重建恢复通过；A/B 提示词分别为 `Native A`、`Native B` |
| 原生通用管理 | 真实 PluginManager、ConfigEditor、Loader；临时 profile | 原生发现、管理范围标识、全局插件配置与单实例保留、配置校验/保存、过期修改拒绝、密钥保留、需要重启结果、普通插件接管和重建恢复通过 |
| 浏览器页面 | 独立无头 Chromium 155.0.8059.84、React 页面、临时原生 profile | 17 项检查通过；无页面运行错误 |

旧版 `0.1.0-prototype.1` 的 17 项核心检查另有 Node 24.21.0 记录；该记录不代表新版新增路径已经在 Node 24 上验收。

核心用例覆盖并发 A/B 请求、同工作区多个对话、配置更新边界、仅关闭一方、工具视图、并发保存、恢复默认、全局插件拒绝工作区覆盖、跨区两端开关、忙碌/排队会话、来源校验、变更目录后的重新绑定、卸载清理以及适配器部分注册失败后的清理。

新增核心检查覆盖普通 Cordis 插件无需管理器适配器即可独立运行、原生 Config 校验、拒绝重复全局激活、全局依赖拒绝、原生操作结果保留、密钥脱敏与保存、根服务泄漏清理、解除接管、原生模块替换后的重新绑定、目录归属变化以及含隐藏密钥列表的配置编辑。

管理范围检查覆盖不支持工作区接管的插件仍可全局启停、候选与已接管状态的区分、浏览清单不导入停用模块，以及已知的全局服务提供者在停用后继续保留全局标识。原生 profile 中额外加载一个依赖 `connection` 与 `workspaceRegistry` 的全局测试插件，验证其配置可保存并重建恢复，而且只保留一个全局注册。

浏览器前 7 项检查覆盖原有工作区功能，另有 10 项覆盖真实原生插件清单与开关、全局配置保存、密钥未展示、需要重启结果如实展示、普通插件直接接管、该插件 A/B 独立配置和单方停用，以及管理范围标识、拒绝接管原因、全局插件配置与单实例保留、原生服务提供者不列为候选。最终普通插件的 A 贡献为空，B 保留 `UI ordinary B`。插件和工作区来自临时验证 profile；截图见 [工作区插件页面](images/workspace-manager-ui.png)。

原生通用管理验证在重建临时 profile 后，A/B 提示词分别为 `ordinary A`、`ordinary B`，Host 全局层没有对应贡献。对不带 HMR 的临时 profile，原生开关返回 `restart-required`；测试仅重建该内存夹具，不重启 DSH 桌面应用。

验证使用独立 SDK、临时 profile 和测试 Agent。模型请求、运行中 DSH 连接及正式 profile 写入均为 0。测试代码随仓库提供，重跑方法见 [README](../README.md)。SDK、临时 profile、机器绝对路径和原始环境收据不公开；本文件记录结果及证据边界。

# 通用插件管理范围

`0.2.0-alpha.1` 在原型的适配接口之上，增加原生插件管理和普通 Cordis 插件直接加载。所有动作通过宿主公开接口执行，不改宿主源码。

| 功能 | 范围 | 是否需要管理器专用适配器 |
| --- | --- | --- |
| 原生插件/组合包发现 | 当前 profile 的原生清单 | 否 |
| 条目与组合包全局开关 | 原生管理器允许寻址的对象 | 否 |
| 活动条目配置编辑 | 原生 ConfigEditor 允许寻址的条目，JSON 配置 | 否 |
| 工作区独立开关与参数 | 可按 Agent 加载的普通 Cordis Host 模块 | 否 |
| 跨工作区操作双端准入 | 所有执行入口接入 `runCrossWorkspace` 的插件 | 是 |
| 任意全局服务、客户端页面或文件副作用的工作区隔离 | 当前版本不提供 | 需要专门设计，单个作用域开关不足以实现 |

## 普通插件直接加载

用户先通过原生开关停用一个全局条目。宿主要求重启时，管理器如实显示结果，实际实例仍运行期间不能接管。通过接管后，各工作区默认关闭，可分别启用。

管理器使用原生 Loader 解析此条目的模块，复用插件导出的 Config 校验配置，并直接调用 Cordis 的插件加载接口。每个 Agent 持有独立的 fiber；其工具、提示词、命令等作用域注册随该 Agent 的配置和生命周期释放。

当前准入依赖为 `systemPrompt`、`tools`、`commands`。无依赖的普通插件也可加载。需要其他服务、带条目级自定义 inject 拦截、受原生管理保护、已经全局活动、或拥有组合树的条目保留全局管理。根 realm 服务审计会拒绝本次实例向全局发布服务；普通模块代码仍然是受信任的同进程代码，这一审计不能证明其没有其他副作用。

如果用户从其他页面重新全局启用被接管的条目，下一次工作区组装会拒绝重复运行。管理器自己的原生启用入口会先要求解除接管。解除接管保留各工作区偏好，并保持原生条目停用。

配置变化只在该 Agent 下一次组装前重新挂载。两个工作区并发时，各自读取自己的配置；切换当前 UI 工作区不会切换另一对话的插件。

## 配置与密钥

全局编辑使用原生 ConfigEditor 的文件锁、校验、原子写入和重组装。编辑器附带读取时的配置摘要，其他页面先保存后会拒绝过期写入。

浏览器输出按原生 schema 的 secret 标记脱敏。JSON 省略这些字段时由服务端保留原值；显式填写可替换密钥。为防止把隐藏凭据移到其他列表成员，JSON 编辑不能改变含隐藏密钥列表的长度；此类成员调整交给原生配置页。未标记为 secret 的字段遵循插件自己的 schema。

## 跨工作区插件

迁移插件通常依赖工作区注册表、会话存储和连接等全局服务。因此直接加载会拒绝这类插件。它们可以在通用管理页进行全局启停与配置编辑；需要按工作区控制迁移时，仍须将所有菜单、拖拽和 RPC 执行入口接入统一的双端检查。

只在管理器里新增一个迁移开关，并不能约束原迁移插件继续开放的全局 RPC。本版本不把这种开关算作工作区隔离，也不修改已经安装的迁移插件。
